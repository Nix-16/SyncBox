## 1. 测试策略

```
        ┌──────────────┐
        │  手工演示     │  S1–S10 场景，M9 验收
        ├──────────────┤
        │  性能基准     │  10k 文件 / 100 MiB 文件 / 空闲占用
        ├──────────────┤
        │  故障注入     │  kill -9、断网、磁盘满、时钟跳变
        ├──────────────┤
        │  集成测试     │  真实 server + 多个 client + 临时目录
        ├──────────────┤
        │  单元测试     │  纯函数、状态机、解析、SQL
        └──────────────┘
```

原则：

1. **可重复**：每个用例使用独立临时目录与独立数据库，测试结束清理。
2. **无外部依赖**：集成测试在进程内启动真实 HTTP 服务端（随机端口），不使用 mock 协议层。
3. **时间可控**：去抖、退避、心跳通过可注入的 `IClock` 控制，避免 `sleep` 拖慢测试。
4. **失败可诊断**：失败时输出请求/响应日志、数据库快照与目录树哈希。

## 2. 测试基础设施（M1 建立）

| 组件 | 说明 |
|---|---|
| `TestServer` | 进程内启动 `syncboxd` 核心，监听 `127.0.0.1:0`，暴露实际端口 |
| `TestClient` | 进程内启动 `SyncEngine`，绑定临时根目录与独立 SQLite |
| `TestClock` | 可手动推进的时钟，替代 `steady_clock` |
| `FaultInjector` | 环境变量/接口触发的故障开关（见 §6） |
| `DirSnapshot` | 递归记录 `(相对路径, 大小, SHA-256, 大小写)` 用于比对 |
| `waitFor(cond, timeout)` | 轮询条件，超时即失败；禁止裸 `sleep` 断言 |
| CI 矩阵 | Linux (GCC 12) / Windows (MSVC 2022) / macOS (Clang 15) |

构建与运行命令在 M1 后写入 [AGENTS.md](../AGENTS.md) 与 README；当前不存在。

## 4. 集成测试：核心同步

每个用例：启动 1 个 `TestServer` + N 个 `TestClient`（各自临时根目录）。

| ID | 场景 | 步骤 | 期望 |
|---|---|---|---|
| TC-100 | 单文件新建传播 | A 建 `a.txt` | B、C 1 个同步周期内出现，hash 一致 |
| TC-101 | 修改传播 | A 改文件 | B 更新，revision+1 |
| TC-102 | 删除传播 | A 删文件 | B 删除，tombstone 存在 |
| TC-103 | 重命名传播 | A 重命名 | B 路径变化，`file_id` 不变 |
| TC-104 | 目录移动 | A 移动整个目录 | B 目录结构与内容一致 |
| TC-105 | 空文件 | A 建 0 字节文件 | 正常同步，hash 为空串向量 |
| TC-106 | 大文件分块 | 100 MiB 文件 | 完整同步，hash 一致 |
| TC-107 | 二进制文件 | 随机 10 MiB | 字节级一致 |
| TC-108 | Unicode 文件名 | `报告-2026.txt`、emoji | 三平台一致 |
| TC-109 | 深层目录 | 20 层嵌套 | 正常创建 |
| TC-110 | 忽略规则 | `*.tmp`、`.git/**` | 不上传、不下行 |

## 6. 故障注入

通过 `FaultInjector` 在指定点注入；环境变量 `SYNCBOX_FAULT=<id>` 或测试 API。

| ID | 故障 | 注入点 | 期望 |
|---|---|---|---|
| FI-01 | 进程立即退出 | 暂存写入后 | 重启重扫，无半文件 |
| FI-02 | 进程立即退出 | 分块上传中 | 重启续传，最终成功 |
| FI-03 | 进程立即退出 | 提交请求发出后、响应前 | 重启同 `op_id` 重试，仅 1 个版本 |
| FI-04 | 进程立即退出 | 目标文件替换后、索引更新前 | 重启比对磁盘，修正索引 |
| FI-05 | 进程立即退出 | 索引更新后、游标推进前 | 重放变更，幂等 |
| FI-06 | 网络完全断开 30 分钟 | 客户端 | 本地操作全部排队，恢复后补齐 |
| FI-07 | 丢包 50% | 网络层 | 退避重试，最终成功 |
| FI-08 | 响应超时但请求已到达 | 代理丢弃响应 | 幂等重试成功，无重复版本 |
| FI-09 | 磁盘满 | 下载落盘 | 目标文件不变，进入 `retry` |
| FI-10 | 磁盘满 | 服务端 blob 写入 | 返回 5xx，客户端重试 |
| FI-11 | 文件被独占（Windows） | 替换 | 重试后成功或进入 `retry` |
| FI-12 | 权限被移除 | 读取文件 | 明确错误，跳过并告警 |
| FI-13 | watcher 事件丢弃 | 测试钩子丢弃 50% | 周期核对补齐 |
| FI-14 | inotify 队列溢出 | 批量 10 万事件 | 触发全量核对，最终一致 |
| FI-15 | 时钟回拨 1 小时 | `TestClock` | 去抖/退避不使用墙上时钟 |
| FI-16 | 服务端崩溃于事务中 | `SIGKILL` | 事务回滚，无半提交 |
| FI-17 | 服务端崩溃于提交后、通知前 | `SIGKILL` | 客户端轮询仍能拿到变更 |
| FI-18 | WS 断开 | 服务端关闭连接 | 客户端重连 + 轮询 |
| FI-19 | 游标过期 | 服务端 GC 后 | `410` → 全量快照 → 一致 |
| FI-20 | 临时文件残留 | 手动放置 `.part` | 启动清理，不误上传 |
| FI-21 | 数据库中损坏一行 | 手动改 hash | 核对发现并修复/告警 |
| FI-22 | 同一 op 双发 | 两个线程同时提交 | 服务端串行化，1 个版本 |

## 8. 性能基准

环境：4 核 / 8 GiB / SSD / 1 Gbps LAN（或回环，注明）。

| ID | 指标 | 目标 | 方法 |
|---|---|---|---|
| PF-01 | 增量单文件延迟 p95 | ≤ 2 s | 1000 次修改，统计从事件到对端落盘 |
| PF-02 | 100 MiB 文件同步 | ≤ 60 s | 单次，含分块校验 |
| PF-03 | 10,000 文件 / 5 GiB 首同步 | ≤ 10 min | 生成固定数据集 |
| PF-04 | 空闲 CPU | ≤ 1% 单核 | 10,000 文件空闲 10 分钟 |
| PF-05 | 常驻内存 | ≤ 200 MiB | 同上 |
| PF-06 | 服务端吞吐 | ≥ 100 ops/s | 50 客户端并发小文件 |
| PF-07 | 事件合并 | ≤ 3 次提交/1000 写 | TC-112 |
| PF-08 | 数据库大小 | 10 万条目 ≤ 100 MB | `entries + versions`（不含 blob） |
| PF-09 | 启动恢复时间 | ≤ 5 s（10k 待办 1000） | 冷启动到可同步 |

基准以 CSV/JSON 记录，M9 生成对比图表；不得以单次运行代替多次取中位数。
